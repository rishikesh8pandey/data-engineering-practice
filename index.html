How it works

  1. Pick a problem. SQL problems have an editor on the page; every problem has a Colab notebook that installs PySpark and loads the data.
  2. Write your answer and run the check.
  3. If it is wrong, the check tells you what kind of thing is off (columns, types, row count, which column) but never the answer.
  4. When you are done, or stuck, read the explanation: the approach, the common wrong answers and why they are wrong.

Who it is for

Freshers and working engineers in India who are preparing for data engineering interviews, or who want to get better at the work itself. The problems use small synthetic datasets with the awkward cases planted on purpose: nulls, ties, duplicates, late records.

The problems listed here are free. Harder problems with detailed explanations will be paid later.

About

NullTrap is built by Rishikesh Pandey, a data engineer who works with PySpark, Databricks and Delta Lake.

Most practice sites test whether you can write a query. In a real pipeline the query is rarely the hard part. The data is: the NULL in a lookup table, the payment that arrives twice, the event that shows up two days late. Every problem here is built around one such trap, and is tagged with it, so you can practise the kind of mistake you keep making.

It is a one-person side project. If something is wrong or unclear, open an issue on GitHub.
